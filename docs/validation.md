# 验证记录

本轮以 700ab48 为基线。写作由一位执行者按相同的事实核对要求完成，在四个隔离工作区编译虚构样例。首页 PDF 可以从 [TeX](../templates/resume.tex) 直接复跑，也可以让助手从 [样例材料](../examples/materials.md) 重新写一份。

| 场景 | 成品 | 核对内容 | Windows 编译与检查 |
| --- | --- | --- | --- |
| 首页后端样例 | 一页 A4 | 实习先讲个人负责的批次重试和数据库写入，测试数据标明样本、轮数与口径。技能用一行，虚构说明用一行。上一版无带验证口径的指标，旧样例的三条技能描述和页尾说明栏目已精简。 | 4.54 秒 |
| 材料少 | 一页可审阅版 | 中文 TXT 带 UTF-16 标记，保留已知教育和课程实践，待确认的日期和联系方式列在 PDF 外。旧脚本读取失败，新脚本正确提取。 | 3.60 秒 |
| 奖项突出及论文冲突 | 一页可审阅版 | 奖项提前，金、银、铜分组，两项金牌同组倒序并保留各自赛区。论文材料冲突时只写本人完成的脚本，把状态和作者顺序集中列为待确认。 | 3.67 秒 |
| 岗位定向及经历丰富 | 两页 A4 | 按招聘要求突出导入、补数、对账与 SQL。省略未掌握的 Kubernetes 和不相关经历。自然排版仍超过一页，调整后首页保留主经历，第二页从完整项目开始。 | 3.93 秒 |

逐页查看了预览，并提取文字核对段落、数值与顺序。Windows 另用系统文件共享锁占用旧 PDF，确认旧文件保留、检查报告指向新生成的 PDF。自动测试核对有无 JPG 或 PNG 时的姓名居中、照片遮挡、篡改模板、旧 PDF、中文 TXT/Word 与当前样例 TeX 和公开 PDF 的文字一致性。

## 调用和耗时

- 默认必读规则仍为一份，AGENTS.md 从 2,366 减到 1,853 个 Unicode 字符，含空白和 Markdown。写作 skill 全文 909 字符，遇到相关问题才查。不含材料、系统提示和助手自身开销。
- Windows + MiKTeX，Python 3.13 + PyMuPDF 1.27.2.3。用同一份新样例 TeX，各跑三次并交替起跑顺序。每次调用一次 `init` 和一次 `build --check`，后者含两次 XeLaTeX、文字检查和预览。基线与本轮的构建中位数为 3.817 秒和 3.795 秒，单机结果没有显示可区分的构建提速。材料少的样例多一次 `read`，耗时约 0.15 秒。
- 没有逐请求 token 数据。以上记录的是规则字符、辅助命令调用和本地耗时，不含模型写作时间或等待时间，也没有测不同助手的出稿质量。

Windows 在本地复跑，Linux 和 macOS 由 GitHub Actions 编译。语言、环境与实际检查结果见[项目检查](https://github.com/Kidding-Ma/ai-auto-resume/actions/workflows/check.yml?query=branch%3Amain)。使用缺少 Adobe-GB1 映射的 Poppler 时可能提不出中文，本轮用 PyMuPDF 核对实际文字。
