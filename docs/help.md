# 使用帮助

首页的两步足够开始。只有遇到问题时，才需要看这里。

## 材料怎么放

“工作区”就是 AI 当前打开的文件夹。已有子文件夹不用移动或改名，不需要建 materials 文件夹。没有旧简历就照首页写 `个人情况.txt`；课程作业、比赛、社团、兼职和志愿活动也可以提供。没有目标岗位或照片也能生成。

支持文字、Word（.docx）、有文字的 PDF、项目资料和代码。扫描件、截图及旧 .doc 能否读取取决于助手；读不成功时应告诉你，不能猜内容。有多张候选照片时，说明用哪张即可。

不要放密码、密钥、身份证号或未获准分享的公司源码。使用云端 AI 前，确认你愿意将这些材料提供给所选服务。

## 电脑需要装什么

让 AI 先试已有环境，能用就直接生成简历；仅排查环境问题时才编译示例。已有工具能用就跳过安装；找不到 `xelatex` 时先查安装路径，缺组件就在原来的 LaTeX 中补齐。

确实没有 LaTeX 时，按系统选一套：

- Windows：[MiKTeX](https://miktex.org/download) 或 [TeX Live](https://www.tug.org/texlive/)。
- macOS：[MacTeX](https://www.tug.org/mactex/)。
- Linux：软件源中的 TeX Live，包含 XeLaTeX 和中文支持。

安装后重开助手和编辑器。MiKTeX 首次编译可能需要联网补组件，按安装提示处理即可。不需要再装第二套 LaTeX。

推荐 VS Code + Codex；已有 OpenCode、DeepSeek Harness 或其他能读写本地文件、运行命令的助手也可以。只会网页聊天的 AI 无法直接完成自动流程。

AI 可以直接运行 XeLaTeX，不要求安装编辑器插件。想手动编辑、预览时再用 VS Code 和 LaTeX Workshop，已有可用插件或配置就保留。本项目的 XeLaTeX 配置不需要 Perl。

Python 3.10+ 只用于辅助脚本，不是生成 PDF 的必需条件。有 Python 时可运行 `python scripts/resume.py doctor` 检查工具。

排版测试已在 Windows + MiKTeX、Linux + TeX Live、macOS + BasicTeX 上通过；不代表所有 AI 客户端都完成过整套实测。

## 生成后还要看什么

投递前核对姓名、联系方式、学历、日期、奖项和本人贡献。AI 会检查内容与整页排版；自动检查不能判断经历真假。具体要求见[写作规则](writing-rules.md)。

材料少也会先做出简历，不必凑经历或数字。重要事实冲突时，AI 会集中问一次；尚未确认的内容列在 `output/review.md`，PDF 标为可审阅版。原 PDF 被阅读器占用时，新结果可能叫 `resume-optimized.pdf`，打开助手最后给出的文件即可。

照片、修改篇幅或切换语言都沿用同一模板。[模板来源与调整](../THIRD_PARTY_NOTICES.md)

## 会不会很费 token

默认只读一份核心指引，先读个人情况和旧简历，缺什么再查补充材料。未变化的材料复用已提取的文字；只在需要代码证据时加载项目分析 skill。修改后才重新编译、检查，不反复生成长报告。

这能减少重复读取和无效尝试；实际消耗仍取决于材料长度、所用模型及返工次数。事实核对和最终 PDF 检查会保留。

## AI 执行时遇到问题

以下操作交给 AI，不要求用户逐条运行：

- Word 读取乱码：优先用 `read` 命令提取到 UTF-8 文件，再读取文字；图片另行查看。
- PDF 检查：优先用 `check` 命令生成检查结果和整页预览，需要时补可选依赖 PyMuPDF。预览工具缺 CMap 等组件时换已有渲染器复核，不能据此改字体或行距。
- 旧副本：从 GitHub 读取最新指引，核对本地 `--version`；过旧时另取新版工具，保留个人材料、旧结果和未提交修改。
- 无法编译或看图：说明具体失败和未完成的检查，不把旧 PDF 当成新结果。

不要把材料或成品提交到公开 GitHub。项目的忽略规则仅保护工具仓库中新加的非公开文件，不能保护其他仓库、已跟踪文件或强制添加的文件。
