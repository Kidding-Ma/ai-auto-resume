# 写中文求职简历

## 一眼能看懂本人解决了什么

- 同一段工作若覆盖两个实质不同的难题，可在同一经历下用短标签分组。标签用能读懂的任务名，例如“批量导入与失败重试”。先写本人负责的关键动作，再交代为什么这么做、怎么验证。每条聚焦一件事，一行说清就停。
- 用“原来怎么失败 / 本人改了哪一步 / 怎么确认改好了”找能写的事实，正文按阅读顺序组织。代码能证明模块行为，署名提交、本人记录或项目文档才能支持个人归因。团队结果留给团队。
- 原材料写“参与库存功能，负责失败后重跑；测试中断后重复提交同批库存，只写入一次”，可写成“实现库存批次重试，回归测试中断后重复提交同一批次，验证库存只写入一次”。同组有两条描述同一个结果时合并。无法支持结果时，写已完成的接口、脚本、实验或回归用例。

## 决定证据能支持哪句话

- 每个比较都问清比较对象、指标口径和场景。测试样本、轮次、延迟分位或测试环境会改变读者理解时，和数值写在同一条。材料给出前后值就用原值，无口径就写完成的工作。把“压测”“本地”“测试集”“原型”等限定留在句子里。
- 出现论文或奖项冲突时，优先用可归属的原件核对，例如带本人信息的录用信或证书。论文官网可核对文献信息，确认不了作者身份和个人分工时只写材料能证明的工作。不同赛区或年份的奖项合并时逐个标明。
- 有招聘要求时，先挑最重要的一两项要求，给每项找一条已有行动作证。调整栏目的优先级和条目的篇幅，保留事实原名。没做过的要求可以空着，不在技能栏补关键词。

## 判断第二页是否值得留

先给最强的经历足够空间，再删赘述、次要步骤、同类旧成果和重复技能。删完仍挤出一段有独立价值的经历，才考虑两页。首页要读到主要资历和强成果，第二页从完整的栏目或条目开始。只剩一个标题、几条弱奖项或一个短段落时，回到一页。渲染后看每页开头和末尾，必要时把完整条目移到一起。
